ServiceAccounts, Roles, RoleBindings, ClusterRoles, and ClusterRoleBindings. The checked
resource references below are literal rendered values; `scripts/helm-contract-test.sh`
also asserts the complete parsed object set and every exact rule set.

## Webhook matrix

| Condition | Scope / object | Exact rules / references |
|---|---|---|
| `webhook.enabled && certAutoGenerate` | release Role `<fullname>-webhook-secret` | core `secrets`: named `get` only on `echo-operator-webhook-ca`; separate unscoped `create` only |
| runtime admission (`webhook.enabled && !createWebhookConfigurations`) | ClusterRole `<fullname>-webhook` | separate unscoped `create` rules for validating and mutating configurations; `get,update,patch,delete` only on `echo-operator.contract-ns.echo.example.com` for each kind |
| runtime predecessor barrier | same ClusterRole | `get` only on `contract-echo-operator-validating` (validating) and `contract-echo-operator-mutating` (mutating) |

| auto-generated conversion | same ClusterRole | `apiextensions.k8s.io/customresourcedefinitions`, `resourceNames=[echoresources.example.com]`, `get,update,patch` only |
| external static conversion / Helm-owned admission | same ClusterRole | no Secret role, no admission create/barrier/mutation rules, and no CRD rule; cleanup rules above are the complete ClusterRole |

### Watched-namespace admission-name correction

Runtime admission `resourceNames` always use the effective watched namespace, matching
Java `registrationBaseName`: `echo-operator.<watched-namespace>.echo.example.com`.
The explicit parsed render with release namespace `release-ns`,
`operator.namespace=watched-ns`, and leader election enabled constrains both validating
and mutating runtime-owner rules to `echo-operator.watched-ns.echo.example.com`.
Its controller Role/RoleBinding remain in `watched-ns`; every binding subject remains a
ServiceAccount in `release-ns`. Release-equal renders remain
`echo-operator.contract-ns.echo.example.com`.

## Parsed isolation outcomes

- Split controller is denied Secret `get`, admission configuration `create`, CRD `patch`, and Lease `update` unless the controller-only lease Role is explicitly enabled.
- Split webhook is denied EchoResource update, Deployment delete, Event create, and every Lease verb.
- External runtime registration keeps admission owner and exact predecessor `get` rules but has neither Secret nor CRD patch rights.
- Cleanup can delete only the runtime stable name; it cannot delete either Helm predecessor name.
- Combined preserves one ServiceAccount; its separate Role/Binding references retain the same release-namespace subject.
