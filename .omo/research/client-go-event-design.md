# Kubernetes client-go event design

Primary sources used:
- client-go: `tools/events/*`, `tools/record/*`
- Kubernetes API types: `staging/src/k8s.io/api/events/v1/types.go`, `staging/src/k8s.io/api/core/v1/types.go`
- Kubernetes API reference: `https://kubernetes.io/docs/reference/kubernetes-api/events/event-v1/`, `https://kubernetes.io/docs/reference/kubernetes-api/core/event-v1/`

## 1) EventRecorder / EventRecorder interface

- `tools/record.EventRecorder` is the emit-only API: `Event`, `Eventf`, and `AnnotatedEventf`. `tools/events` re-exports the same recorder interfaces as aliases, and adds `EventRecorderLogger` with `WithLogger`. [client-go/tools/record/event.go#L92-L127](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/record/event.go#L92-L127) [client-go/tools/events/interfaces.go#L29-L31](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/events/interfaces.go#L29-L31)
- A recorder is created by a broadcaster, not by the API client directly. `NewRecorder(...)` captures the scheme and controller name, derives `reportingInstance` from `<controller>-<hostname>`, and emits `watch.Added` events into the broadcaster. [client-go/tools/events/event_broadcaster.go#L163-L168](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/events/event_broadcaster.go#L163-L168) [client-go/tools/events/event_recorder.go#L73-L98](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/events/event_recorder.go#L73-L98)
- The migration adapter picks `events.k8s.io/v1` when discovery says it exists; otherwise it falls back to the legacy core/v1 recorder. [client-go/tools/events/event_broadcaster.go#L413-L447](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/events/event_broadcaster.go#L413-L447)

## 2) EventBroadcaster

- `EventBroadcaster` fans events out to sinks, watchers, and loggers. The new implementation uses `watch.NewLongQueueBroadcaster(maxQueuedEvents, watch.DropIfChannelFull)` with a queue size of 1000. [client-go/tools/events/interfaces.go#L33-L64](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/events/interfaces.go#L33-L64) [client-go/tools/events/event_broadcaster.go#L48-L53](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/events/event_broadcaster.go#L48-L53) [client-go/tools/events/event_broadcaster.go#L199-L203](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/events/event_broadcaster.go#L199-L203)
- `StartRecordingToSinkWithContext` starts two background loops: `refreshExistingEventSeries` every 30 minutes and `finishSeries` every 6 minutes, then starts the watcher that forwards emitted events to the sink. [client-go/tools/events/event_broadcaster.go#L391-L396](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/events/event_broadcaster.go#L391-L396) [client-go/tools/events/event_broadcaster.go#L126-L160](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/events/event_broadcaster.go#L126-L160)
- The broadcaster also has structured/log logging paths and a `StartEventWatcher` API for custom consumers. [client-go/tools/events/event_broadcaster.go#L312-L360](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/events/event_broadcaster.go#L312-L360)

## 3) EventCorrelator / spam filter / aggregate filter

- `EventCorrelator.EventCorrelate` runs in this order: aggregate similar events, count exact duplicates, then spam-filter the result. If the spam filter rejects it, the event is skipped entirely. [client-go/tools/record/events_cache.go#L509-L526](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/record/events_cache.go#L509-L526)
- The spam filter is a per-`source + object + type` token bucket. `getSpamKey` ignores the message, and `Filter` drops events once the bucket is empty. [client-go/tools/record/events_cache.go#L69-L82](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/record/events_cache.go#L69-L82) [client-go/tools/record/events_cache.go#L90-L152](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/record/events_cache.go#L90-L152)
- The aggregate filter groups on source, involved object, type, reason, reporting controller, reporting instance, and message. It keeps a set of unique messages; once the set reaches the threshold it emits a synthetic aggregate event with a combined message. [client-go/tools/record/events_cache.go#L154-L178](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/record/events_cache.go#L154-L178) [client-go/tools/record/events_cache.go#L233-L297](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/record/events_cache.go#L233-L297)
- Exact duplicates are counted separately by `eventLogger`: on a cache hit it reuses the original name/resourceVersion, increments `Count`, and builds a strategic-merge patch that omits count/lastTimestamp/message fields before sending. [client-go/tools/record/events_cache.go#L299-L370](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/record/events_cache.go#L299-L370)
- After a successful write, `UpdateState` stores the server-returned `Count`, `FirstTimestamp`, `name`, and `resourceVersion` so later duplicates patch the right object. [client-go/tools/record/events_cache.go#L372-L387](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/record/events_cache.go#L372-L387)

## 4) Event fields relevant to aggregation

- In `events.k8s.io/v1`, the aggregation-relevant fields are `eventTime`, `series`, `reportingController`, `reportingInstance`, `action`, `reason`, `regarding`, `related`, and `type`; the deprecated compatibility fields are `deprecatedSource`, `deprecatedFirstTimestamp`, `deprecatedLastTimestamp`, and `deprecatedCount`. [Kubernetes API reference: Event](https://kubernetes.io/docs/reference/kubernetes-api/events/event-v1/) [kubernetes/staging/src/k8s.io/api/events/v1/types.go#L28-L99](https://github.com/kubernetes/kubernetes/blob/0ad5530cfdf4125d6b3a1a2cfc694f80570e6914/staging/src/k8s.io/api/events/v1/types.go#L28-L99)
- The `Series` field is the marker for a singleton vs a series event in the new API. `EventSeries` carries `count` and `lastObservedTime`. [kubernetes/staging/src/k8s.io/api/events/v1/types.go#L45-L110](https://github.com/kubernetes/kubernetes/blob/0ad5530cfdf4125d6b3a1a2cfc694f80570e6914/staging/src/k8s.io/api/events/v1/types.go#L45-L110)
- In core/v1, the legacy aggregation fields are `FirstTimestamp`, `LastTimestamp`, `Count`, `Source.component`, `Source.host`, `EventTime`, `Series`, `Action`, `Related`, `ReportingController` (protobuf name `reportingComponent`), and `ReportingInstance` (`reportingInstance`). [Kubernetes API reference: Event](https://kubernetes.io/docs/reference/kubernetes-api/core/event-v1/) [kubernetes/staging/src/k8s.io/api/core/v1/types.go#L7631-L7694](https://github.com/kubernetes/kubernetes/blob/0ad5530cfdf4125d6b3a1a2cfc694f80570e6914/staging/src/k8s.io/api/core/v1/types.go#L7631-L7694)
- The Kubernetes API docs explicitly say events are best-effort, can evolve, and consumers should not rely on a stable meaning or continued existence for a given `Reason`. [Kubernetes API reference: Event](https://kubernetes.io/docs/reference/kubernetes-api/events/event-v1/) [kubernetes/staging/src/k8s.io/api/events/v1/types.go#L28-L34](https://github.com/kubernetes/kubernetes/blob/0ad5530cfdf4125d6b3a1a2cfc694f80570e6914/staging/src/k8s.io/api/events/v1/types.go#L28-L34)

## 5) EventSeries and series updates

- `EventSeries` is reporter-driven: the API comment says reporters decide how often to update it, and the client-go broadcaster shows the default heartbeat strategy. [kubernetes/staging/src/k8s.io/api/events/v1/types.go#L101-L110](https://github.com/kubernetes/kubernetes/blob/0ad5530cfdf4125d6b3a1a2cfc694f80570e6914/staging/src/k8s.io/api/events/v1/types.go#L101-L110) [Kubernetes API reference: Event](https://kubernetes.io/docs/reference/kubernetes-api/events/event-v1/)
- In client-go, the first repeat of an isomorphic event creates `Series{Count: 2, LastObservedTime: now}` and returns a deep copy for patching; later repeats just increment `Series.Count` and refresh `LastObservedTime` in cache. [client-go/tools/events/event_broadcaster.go#L170-L206](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/events/event_broadcaster.go#L170-L206)
- `refreshExistingEventSeries` re-patches cached series events to keep them alive, and `finishSeries` flushes a final patch when the last observed time is older than 6 minutes, then removes the cached series. [client-go/tools/events/event_broadcaster.go#L126-L160](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/events/event_broadcaster.go#L126-L160)

## 6) Create vs patch vs update

- New events API path: if `Series != nil`, `recordEvent` builds a strategic-merge patch and calls `Patch`; otherwise it clears `ResourceVersion` and calls `Create`. If patch/create returns `AlreadyExists` for a series event, the code retries because a concurrent emitter may have created the same event. [client-go/tools/events/event_broadcaster.go#L230-L280](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/events/event_broadcaster.go#L230-L280)
- Legacy core/v1 path: the correlator returns a patch when it has a prior observation, and `recordEvent` calls `Patch` when `updateExistingEvent` is true; otherwise it calls `Create`. [client-go/tools/record/event.go#L294-L376](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/record/event.go#L294-L376)
- `Update` exists on the `EventSink` interface for compatibility, and `EventSinkImpl` exposes it, but the broadcaster code paths shown above do not use `Update` for aggregation. [client-go/tools/events/interfaces.go#L66-L74](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/events/interfaces.go#L66-L74) [client-go/tools/events/event_broadcaster.go#L83-L105](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/events/event_broadcaster.go#L83-L105)

## 7) Constants / defaults

- Correlator defaults: LRU cache `4096`, aggregate after `10` similar events in `600s` (10 minutes), spam burst `25`, spam refill `1/300 QPS` (1 event every 5 minutes). [client-go/tools/record/events_cache.go#L35-L49](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/record/events_cache.go#L35-L49)
- Broadcaster defaults: `maxQueuedEvents = 1000`, `finishTime = 6m`, `refreshTime = 30m`, `maxTriesPerEvent = 12`, `defaultSleepDuration = 10s`. [client-go/tools/events/event_broadcaster.go#L48-L56](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/events/event_broadcaster.go#L48-L56)
- Both the new and legacy correlators use the same default aggregation constants unless overridden via `CorrelatorOptions`. [client-go/tools/record/events_cache.go#L424-L506](https://github.com/kubernetes/client-go/blob/37dca455f183f431f3b95c90c4dc66b1c19659ff/tools/record/events_cache.go#L424-L506)
